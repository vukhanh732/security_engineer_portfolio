SUPPLY CHAIN · CVE-2023-34362 · JUL 2026

MOVEit: a single SQL injection, thousands of victims

The lesson: internet-facing software that stores sensitive files needs urgent patching, least privilege, and detection tied to the data it protects.

What happened

In May 2023, the CL0P group exploited CVE-2023-34362 in MOVEit Transfer before defenders had a patch. The unauthenticated SQL injection exposed the product's database and enabled deployment of the LEMURLOOT web shell, which supported file theft at scale.

Why the impact spread

MOVEit sits on the internet by design and holds files transferred between organisations. That gave one pre-authentication flaw a short path from a public endpoint to concentrated, sensitive data. The campaign also showed how a vulnerability in one widely deployed supplier can become an incident for every customer.

How this maps to MITRE ATT&CK

T1190Exploit Public-Facing Application: reach the vulnerable endpoint without authentication.
T1505.003Web Shell: deploy LEMURLOOT for persistence and file access.
T1213Data from Information Repositories: collect files held by the transfer service.

What I would build

Maintain a high-priority inventory of edge-facing products and subscribe it to vendor and CISA alerts. Apply emergency isolation and patching for known exploitation. Add least-privilege database access, monitor for unexpected files in MOVEit's web directory, and alert on unusual downloads or admin activity. A decoded SQL injection rule in SentryNode adds defence in depth, but the vendor patch remains the primary control.
