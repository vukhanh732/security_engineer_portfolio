MOVEit: a single SQL injection, thousands of victims

What happened

In 2023, an unauthenticated SQL injection flaw in MOVEit Transfer, a widely used managed file-transfer product, was exploited at scale before a patch was available. Attackers used it to reach the underlying database and exfiltrate files from a large number of organisations that used MOVEit to move sensitive data.

The likely technical root cause

A public-facing web endpoint built a database query from request input without adequately parameterising or validating it, letting attacker-supplied input change the query's structure. Because MOVEit sits deliberately at the edge of a network — its entire job is accepting files from external parties — a flaw here had an unusually direct path from internet-facing input to the data store, with no additional network segmentation to slow an attacker down.

What I'd build to detect or prevent this

This is squarely the pattern SentryNode's SQL injection rule targets — matching injection patterns against decoded request payloads at the edge, rather than trusting the application layer alone. It's also a case for defence in depth beyond detection: database accounts for internet-facing services should carry the minimum privilege needed, so that even a successful injection can't reach the full dataset. And because internet-facing file-transfer software is exactly the kind of dependency Gatekeeper's scanning is meant to flag, staying current on vendor advisories for edge-facing software matters as much as scanning your own code.
